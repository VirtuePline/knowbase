# 工厂维保 / MES 运维知识库助手

面向工厂设备维保与 MES 系统运维的知识库问答服务：上传维保工单、故障台账、MES 运维记录与操作手册，优先给出有依据的解决方案；知识库没有直接方案时，可使用联网搜索提供带来源的公开参考。

## 能力边界

| 能做 | 不做 |
|---|---|
| 优先按文档内容回答故障排查、MES 报错处置 | 没有依据的方案、参数、型号，一律不编 |
| 表格类记录按「编号 / 故障现象 / 处理方案 / 运维时间 / 运维人 / 处理结果」整理 | 猜测未记录的接口逻辑、版本行为 |
| 多份历史记录冲突时全部列出并提示现场核实 | 用通用经验补充故障原因 |
| 知识库无直接方案时，联网查找公开参考并标明来源 | 把网上通用方案当作本站设备已经验证的处置记录 |
| 搜索不可用或仍无依据时明确说明未找到方案 | 上传 / 删除等管理操作（只在面板执行） |

## 快速开始

使用 Python 3.12，并先启动 MongoDB。默认数据库地址为 `mongodb://127.0.0.1:27017`，数据库名为 `knowbase`；可通过 `config.local.yaml` 的 `database` 段或 `KB_MONGO_URI` 环境变量指定其他地址。

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt

# 可选：新建 config.local.yaml 填入密钥，见下文「配置」

python scripts/seed_demo.py       # 生成演示数据（虚构内容，生产前删除）
python -m app.cli ingest knowledge_base/demo
python -m app.cli serve
# 检索端（只读）：http://127.0.0.1:8000
# 管理端（上传 / 编辑）：http://127.0.0.1:8001
```

未配置 `llm.api_key` 时不会调用模型：文档分析使用本地规则，问答优先提取原文中的处理方案与记录结果，不做推断。只包含问题描述的命中不会被当成已找到解决方案。

问答正文不单独列出来源，统一在「参考来源」中查看。记录直接引用的文档库文档放在该记录的索引位置下方，可点击文档名预览。快速模式、原文摘录和大模型整理均支持；同一记录内的重复引用只展示一次，已删除或未就绪的文档自动跳过，引用文档不参与本次检索评分。

联网搜索使用独立的密钥；未配置 `web_search.api_key` 时不会发送搜索请求，仍可使用本地知识库。

本地嵌入与重排序独立于问答模型运行。嵌入模型首次使用可能下载文件；离线机器需要预先准备 `data/models/fastembed` 与 `data/models/bge-reranker-base`。不使用本地模型时，可在配置中关闭 `embedding.enabled` 和 `rerank.enabled`，保留关键词检索。

## 文档分析与端口隔离

- 上传时先去除目录、封面、版权页、页眉页脚等非主要内容，按 PDF 书签、章节标题和正文主题归并结构段，不按页总结；每个结构段再生成摘要，分析失败不会退回全量分块。
- 摘要只保留主题、问题类别、通用原则和安全边界；日期、人员、单条工单 / 流水、具体阈值等细节保留在原文中，不进入摘要。
- 检索匹配章节标题与摘要，原文和表格作为元数据随命中返回。原始文件保存在 `data/raw/`，可预览和下载。
- 上传时自动为文档判定分类（MES系统 / 厂商系统 / 硬件问题 / 网络问题 / 流水线问题 / 流程问题 / 常识库 / 其他）：优先由模型判定，模型不可用时退回关键词规则。分类存入 MongoDB 登记表，文档列表可按「日期」或「类型」分组查看并按分类筛选，管理端可下拉修正；分块中也保留分类。
- 文档可记录网络信息（监控网段、设备 IP、网关、VLAN 等）：字段定义保存在数据库中，管理端「网络字段」弹窗里可新增、改名、换类型、加选项、删除，不需要改代码。取值按类型校验并规范化（网段支持逗号分隔多个，纯 IP 按 /32 归一），预览弹窗中管理端可编辑、查询端只读；文档列表以标签展示网段 / IP。首次建库自动写入默认字段，之后完全以数据库为准。
- Markdown / TXT 可直接在线编辑；其他格式可下载修改后通过「替换」重新上传，替换保留原文档 ID。
- 检索端只挂载问答、列表、预览和下载接口，不挂载上传、替换、编辑、删除或重建接口。
- 管理端提供完整功能，默认仅监听 `127.0.0.1:8001`。端口在 `config.yaml` 的 `server` 段配置，且两个端口不能相同。
- 已入库文档可执行 `python -m app.cli reanalyze`，按当前规则重新生成摘要索引。

## 配置

所有参数写在项目根目录的 YAML 文件中，修改后重启服务生效：

| 文件 | 内容 | 是否提交 |
|---|---|---|
| `config.yaml` | 模型协议与地址、检索阈值、切块大小、服务端口等共享配置 | 提交 |
| `config.local.yaml` | 本机私有配置（密钥、本机端口等），按段深度合并覆盖 `config.yaml` 的同名项 | 不提交（已在 `.gitignore`） |

`config.local.yaml` 只需写要覆盖的项，例如：

```yaml
llm:
  api_key: "sk-xxxx"
```

拼错的配置项、超出范围的值（如 `min_coverage` 不在 0~1）会在启动时直接报错，不会被静默忽略。

旧版 `retrieval.weak_signal_rerank_factor` 随弱信号惩罚规则撤回而废弃；新版兼容读取并输出警告，该值不再影响检索。升级后可从 `config.yaml` 和 `config.local.yaml` 删除该项。旧镜像若因私有配置残留此项而反复报「未知配置项」，删除 `config.local.yaml` 中该项后重启容器即可；应用代码或镜像内的共享配置更新则需重新构建镜像，离线部署时需导入新镜像并重新创建容器。

管理端（8001）始终要求登录，旧的 `auth.enabled: false` 也不会放行管理端。可在 `config.local.yaml` 中设置初始管理员账号和独立密码：

```yaml
auth:
  enabled: true
  admin_user: admin
  admin_password: "请替换为本机独立的长密码"
```

首次启动管理端时会创建该账号；已有同名账号的密码以 MongoDB 中的记录为准，修改 YAML 不会重置已有账号密码。共享配置不包含默认密码。首次未配置密码时，系统生成随机密码，写入 `data/index/bootstrap-admin.txt`，仅供本机管理员读取；妥善保存后可删除该文件。

## 登录、注册与追踪

- 打开 8001 端口，未登录时进入 `/login`；已设置密码的账号登录后默认打开「新增运维记录」。查询端仍默认打开智能问答。
- 管理员可从账号入口进入 `/register`，填写英文账号和用户名，无需设置密码。账号为 3–32 位字母、数字、下划线、点或短横线，以英文字母开头并规范为小写；用户名支持 1–32 位中文、字母、数字、下划线、点和短横线，首位为中文、字母或数字。账号与用户名均可登录，不能与其他账号的任一登录名重复。普通账号不能打开注册页面或调用注册接口。注册不会切换管理员的当前登录会话，也不能覆盖已有账号。
- 新注册账号的初始密码为空，首次登录时输入账号或用户名、将密码留空。登录后必须先在 `/change-password` 设置并确认 8–128 位非空密码，才可进入业务页面或调用管理接口；完成设置后空密码立即失效。之后使用英文账号或中文用户名加本人密码登录。
- 管理员可通过侧栏「修改密码」更改自己的密码，需核验当前密码并重复输入新密码；普通账号也可修改自己的密码。修改成功后保留当前浏览器的新会话，其他旧会话立即失效，需用新密码重新登录。接口不能指定其他账号作为改密目标。
- 已有账号的密码不会因升级被清空；首次管理员初始化仍使用上面的私有配置或随机初始化凭据。
- 新上传文档及新增记录的 `uploaded_by` 由服务端绑定当前会话的稳定账号，页面可同时展示中文用户名，不能通过客户端伪造归属。编辑、替换和重复上传不会把已有记录的上传人改成编辑者；早期未记录上传人的文档保留空值。
- 在「问题时间线」点击「追踪」，进入同一新增页面并显示关联的父问题；保存后生成独立记录，持久化 `parent_id` 和 `root_id`，支持继续追踪子记录。
- 时间线保留原分类、日期排序及卡片样式，只增加父问题、上传人、追踪数量等信息。追加不会覆盖父记录的内容或解决状态。
- 普通新增、编辑和保存完成都会清理追踪表单上下文，避免误关联。已有记录的父关系不能改动；有直接追踪记录的父记录不能删除，需先处理子记录，避免留下断开的关系。

## Docker 部署

镜像只包含代码、Python 依赖和 `data/models` 中的两个模型目录；私有配置、原始文档、索引、图片和演示文档都不会打进镜像。构建前请准备好模型目录，并创建 `config.local.yaml`（不需要覆盖任何参数时可写入 `{}`）。

```bash
# 本机构建并启动
docker compose up -d --build

# 查询端：http://localhost（默认宿主机 80 端口）
# 管理端：http://127.0.0.1:8001（仅宿主机可访问）
```

Compose 将 `data/raw`、`data/index`、`data/images` 分别挂载到容器，模型从镜像读取；`config.local.yaml` 只读挂载。修改私有配置后重启容器，修改代码或共享配置后重新构建镜像。

MongoDB 由外部提供，默认连接宿主机 `host.docker.internal:27017`；Linux 通过 `host-gateway` 映射该名称。MongoDB 需要监听容器可达的宿主机地址；监听回环地址的数据库不能通过该映射访问。可用环境变量覆盖地址（示例为 PowerShell）：

```powershell
$env:KB_MONGO_URI = "mongodb://数据库主机:27017"
$env:KB_IMAGE = "ag-kb:0.2.0"
docker compose up -d --build
```

端口可通过 `KB_SEARCH_PORT`、`KB_ADMIN_PORT` 覆盖；管理端的宿主机绑定始终为 `127.0.0.1`。容器内保持监听 `8000` / `8001`，请勿在私有配置中改动这两个容器端口。

离线发布时使用明确的镜像版本，并同时准备 Compose 文件和目标机器自己的私有配置：

```bash
# 有网络的构建机；模型需提前准备
docker build -t ag-kb:0.2.0 .
docker save -o ag-kb-0.2.0.tar ag-kb:0.2.0

# 目标机器
docker load -i ag-kb-0.2.0.tar
docker compose up -d --no-build
```

升级前备份 MongoDB 与三个业务文件目录，并保管好私有配置。只备份 `data/index` 无法恢复文档登记、账号和审计数据；这些内容位于 MongoDB。

## 模型接入

通过 OpenAI 兼容的 `/chat/completions` 协议接入，在 `config.yaml` 的 `llm` 段配置：

| 场景 | 配置 |
|---|---|
| DeepSeek | `base_url: https://api.deepseek.com/v1`、`model: deepseek-flash` |
| 内网模型 / 兼容网关 | `base_url` 指向内网地址 |

改完先自检，确认模型名称与密钥可用：

```bash
python -m app.cli checkllm
```

返回「连通性：通过」才会进入正常模型作答；失败时会打印服务端原始错误，例如模型名称不被支持时会直接列出可用名称。问答中的模型调用失败不会中断服务：有原文方案时仍可直接返回方案，否则尝试联网参考或明确提示方案缺失。

## 联网参考

知识库优先提供解决方案。只有本地记录无法直接回答时，才尝试 [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)。搜索结果会与知识库来源区分，并保留原始网页链接；公开参考不代表已经在本站设备上验证。未找到可靠方案时只展示相关参考或明确说明无结果，不补写步骤和参数。

在 `config.local.yaml` 中配置独立的搜索密钥：

```yaml
web_search:
  enabled: true
  api_key: "tvly-请替换为自己的搜索密钥"
  base_url: https://api.tavily.com
  timeout: 15
  max_results: 5
```

也可设置 `KB_WEB_SEARCH_API_KEY` 环境变量（优先于 YAML）；Compose 已透传该变量。`web_search.enabled: false` 可完全关闭联网参考。无密钥、超时、搜索服务异常或空结果时明确提示暂无方案，相关原文仍可在来源中查看。搜索失败不会中断问答。模型不可用时只提供网页参考，不把搜索摘要冒充为已确认方案。

搜索只发送当前问题，经规则屏蔽常见密码／token 字段、私有 IP 和 MAC；不发送会话历史、知识库原文或上传附件。规则脱敏不覆盖所有业务敏感信息，含内部项目名称等内容的问题应自行脱敏或关闭联网搜索。服务只读取搜索接口返回的摘要，不主动抓取结果网页。

## 检索与兜底规则

1. 分词保留设备编号、报错码、版本号整体，避免 `E-1024` 被拆碎。
2. BM25 关键词召回与向量语义召回按 RRF（倒数排名融合）合并，再由本地 Cross-Encoder 对候选重排序。嵌入失败时降级为 BM25，重排序失败时保留融合排序。
3. 覆盖率 = 查询词中在文档库里出现过的词，被该条命中的比例。关键词覆盖率、语义相似度、重排序分数中任一路达到对应门槛即可进入本地回答；全部低于门槛时尝试联网参考，无可用搜索时返回无方案提示。
4. 问题点名厂商时，相关厂商文档优先参与排序。命中来自不同文档且分值接近时，追加「多条历史记录存在差异，请运维工程师现场核实」。
5. 本地记录不足以生成直接方案时尝试联网搜索；仍无方案时明确说明缺少依据。相关记录和网页摘要可作为参考展示，不能当作已确认的解决方案。

阈值与候选数量都在 `config.yaml` 中可调：`retrieval.min_coverage`、`retrieval.semantic_threshold`、`rerank.threshold`、`rerank.candidates`。上线前请使用真实故障问题与无答案问题同时验证，避免仅提升召回而增加错误回答。

### 故障匹配与来源指标

召回排名靠前不代表与问题属于同一种故障。作答前会核对问题与记录标题、故障现象中的明确设备及故障类型；例如「电脑开不了机」不会直接采用「音响没声音」的接线方案。表格包含多条问题时还会逐行核对。无法确定冲突时保留候选；IP、配置、清单和台账统计等信息查询仍沿用原有检索流程。

来源中的指标分别展示，不能互相替代：

- **排序分**：RRF 排名融合结果，只用于当前问题的候选排序，不是相关概率，不能跨问题比较。两路检索均排名第一时分数约为 `0.032787`，不同问题可能得到相同排序分。
- **关键词覆盖**：查询关键词的加权覆盖率。
- **语义相似度**：向量余弦相似度，不是答案正确率；仅实际进行向量检索时展示。
- **重排分**：精排模型对问题和片段的分值；快速模式或未执行精排时不展示，实际计算结果为零时仍显示零。
- 完整台账扩展的片段若未单独检索评分，会标为「台账上下文」，不会借用其他片段的分数。旧浏览器历史只有旧分数时标为「历史排序分」；联网网页不混用本地指标。

## 格式说明

- 支持：PDF（文本层）、DOCX、XLSX/XLSM、CSV、TXT、MD。
- 不支持：旧版 `.doc` / `.xls`（请另存为新格式）、扫描版 PDF（无文本层，需先 OCR）。
- Excel 每个工作表按列读取，首行视为表头；合并单元格只保留左上角值。

## 安全提示

- 检索端只读知识库；管理端只写入本项目知识库，不连接或修改 MES / PLC / WMS 生产系统。
- 入库前请对含账号、密码、内网地址的文档做脱敏。
- 启用模型分析时，上传文档的章节原文会发送到模型服务；问答时也会发送命中的片段。如文档涉密，请保持 `llm.api_key` 为空或改用内网模型。
- 联网搜索另受 `web_search` 配置控制；如问题本身涉密，请关闭该功能。搜索密钥和模型密钥均只通过本机私有配置或运行时环境变量提供。
